Getting Started

From a fresh clone of the Go implementation to switching a light, in five steps, then the same in your own program. You need Go 1.26 or later on Linux, macOS or Windows, on the same network as your CLUs, and Grenton Object Manager for the first download.

1Clone

git clone https://github.com/osieckiAdam/grenton-core-go.git
cd grenton-core-go

There is no separate build step: every go run below compiles the example and starts it. The library uses the standard library only, so nothing is downloaded.

2Find the IP address and PIN

In Object Manager, select the mobile interface (Interfejs mobilny) in the tree on the left and click Send to mobile devices (Wyślij na urządzenia mobilne). The dialog shows, top to bottom, the IP address of the computer running Object Manager, the port, and the token: your PIN.

The screenshot hides the address and port; your dialog shows them above the token. Keep the dialog open for the next step.

3Download the interface

go run ./examples/fetch-interface 192.168.1.50 dist/interface.zip 149 853

Type the PIN as the dialog shows it, space included. If the port is not 9998, append it to the address: 192.168.1.50:9999. The saved file lets every next step run without a PIN.

The file holds the encryption key of your CLUs. Keep it private, like a password; it is written readable by you only, and dist/ is git-ignored.

Without a PIN, the project file saved in Object Manager (.omp) works too: go run ./examples/import-project house.omp reads the interface and lists the devices.

4List your devices

go run ./examples/list-devices dist/interface.zip

This works offline. Each device lists its entities by id and name:

switch "Living room ceiling" — page SALON
  k3Xq9TzA_0: Living room ceiling

At the end you also see the hardware shown by several widgets, such as a thermostat that appears on two pages under two names.

5Watch and control

See every entity's live state, then the changes as they happen. This is read-only:

go run ./examples/watch-state dist/interface.zip 30

Turn a light on and off with an id from step 4. This changes your house; the example waits for the CLU to confirm:

go run ./examples/switch-light dist/interface.zip k3Xq9TzA_0 on
go run ./examples/switch-light dist/interface.zip k3Xq9TzA_0 off
On macOS, run these from Terminal.app: local-network privacy silently blocks UDP for programs started from an editor's terminal, unless you allow the editor in System Settings → Privacy & Security → Local Network. On Linux and Windows the firewall must allow inbound UDP to the program (Windows asks on the first run). A CLU with several network interfaces may answer from another address: add -any-source to watch-state.

Use the library in your program

Add the module to your own Go module:

go get github.com/osieckiAdam/grenton-core-go@v0.15.0

A devices.System runs the whole installation: one session per CLU, the state they push, and every device of the interface. Make it from Object Manager (while its dialog is open), start it, and control an entity by the id list-devices printed. Subscribe before you send, so the confirmation cannot be missed:

sys, err := grenton.FromObjectManager(ctx, "192.168.1.50", "149 853", devices.SystemConfig{})
if err != nil {
	log.Fatal(err)
}
sys.Start() // returns when every CLU has answered or timed out
defer sys.Stop()

lamp, ok := sys.Entity("k3Xq9TzA_0").(*devices.Switch)
if !ok {
	log.Fatal("no switch k3Xq9TzA_0")
}
updates, cancel := lamp.Updates() // a flag: read the getters when it fires
defer cancel()
if err := lamp.TurnOn(); err != nil {
	log.Fatal(err)
}
<-updates
on, known := lamp.IsOn()
fmt.Println("on:", on, "known:", known)

Every later start can skip Object Manager: save the archive once (as fetch-interface does) and start from it, or read the project file:

project, err := os.ReadFile("house.omp")
if err != nil {
	log.Fatal(err)
}
// "" takes the project's only interface.
sys, err := grenton.FromProject(project, "", devices.SystemConfig{})
if err != nil {
	log.Fatal(err)
}
sys.Start()
defer sys.Stop()
for _, d := range sys.Devices() {
	fmt.Println(d.Kind, d.Name)
}

Entities are the types of package devices (*devices.Switch, *devices.DimmableLight, *devices.Cover, *devices.Thermostat, …). Their getters read the pushed state and never block on the network; their intents send a command and wait for the CLU's reply. System.Stop ends every socket, timer and goroutine.
